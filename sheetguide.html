IMS Sheet App User Guide

This guide is for the Google Sheets + Apps Script IMS web app. It follows the Sheet App's current modules, validation rules and operating sequence: set up masters first, register the item, then use the correct operational module for every physical or commercial event.

Sheet App Principles

Know what each module is responsible for

The Sheet App works best when users record each event in the module that owns that event instead of manually changing status or location.

Inventory = current physical state

Stock Inventory tells you where an item is now, its current status, and its chronological history. It is not where users manually create physical events.

Movement = physical transition

When an item physically changes location, use Movement. Starting a movement puts the item In Transit; arrival applies the final location and status.

Documents = commercial agreement

Documents preserve the PO, invoice, period and permanent commercial item relationship. A physical return does not remove an item from the PO history.

Do not update the Google Sheet manually to simulate an operation. The web app applies the related validation, status, location and history changes together.

01 · Masters & Registration

Set up Global Settings and Businesses first

The Masters & Registration module contains the controlled reference data used by the rest of the Sheet App.

Global Settings

Maintain controlled values such as warehouse, item type, unit, category, size, grade, PPF, connection, range, brand, model and weight unit. Reuse existing types; do not create arbitrary duplicates.

Businesses

Maintain complete business information and business roles such as Supplier, Client and Service Provider. Business Details is for company information and commercial documents, not operational item history.

Item Type controls quantity mode. A Single item locks Default Qty to 1; unrelated master types do not control quantity.
Use clean master values. If a required warehouse, business or specification is missing, add the correct master instead of typing a workaround into an operation.
Disable instead of inventing replacements. Keep master data consistent so dropdowns and validation remain dependable.
02 · Registration

Create the physical item's permanent identity

Owned and Rent-to-Rent items are imported separately. The Sheet App uses Excel files with the expected first-sheet column structure.

Owned Item Import

Use for Wellora-owned equipment. Each physical serialized item uses its Wellora SN and its purchase/master information. Duplicate serial numbers are checked before records are written.

R2R Item Import

Use for supplier-owned Rent-to-Rent equipment. Each item uses its R2R SN, supplier, Our PO, rental dates and destination warehouse information.

03 · Main Workspace · Movement

Record every physical location change

Movement handles supplier, warehouse and client transitions. The eligible-item picker is filtered by the selected movement type and source.

Receive from Supplier

Supplier → Warehouse. Reference: Wellora PO. Start = In Transit; arrival normally makes the item Available in the destination warehouse.

Warehouse Transfer

Warehouse → Warehouse. Reference: Internal Transfer No. Use this for physical movement between Wellora locations.

Deliver to Client

Warehouse → Client. Reference: Client PO. Arrival makes the item At Client at the selected client location.

Return from Client

Client → Warehouse. Reference: Receiving No. Use this when the item physically returns from the client.

Item selection

Use Fast Pick when you know the exact Wellora SN / R2R SN or exact Description, or browse eligible items. Browse pages are limited to 20 items for operational selection.

05 · Stock Inventory

Use Inventory to understand the current state

Stock Inventory is the operational view of item master data plus current status/location. It is optimized for browsing and inspection rather than editing physical events.

Inventory list

Browse current items with server-side Sheet App paging. The inventory list uses 50 records per page.

Item Details

Open an item to see complete master information with current Status and Current Location shown prominently.

Chronological History

Item history is loaded when Details opens and can include registration, movement, service, reservation, documents/extensions, incidents and disposition.

Inventory tells you what is true now. Use the source operational modules to create or correct the event that changes that state.
06 · Documents

Preserve permanent commercial relationships

Documents represents the commercial agreement and scope. It is deliberately separated from the item's current physical status/location.

PO-linked items are permanent

Once an item is linked to a PO, the commercial relationship remains in that PO record even if the item later returns to a warehouse.

No current status/location in PO item list

Current physical Status and Current Location belong to Stock Inventory. Documents focuses on the commercial record.

Extension = new official PO

An extension requires a new PO number, agreed amount, currency, date range/new due date and the selected extended items. The old PO remains historical and immutable.

Invoices can span POs

The commercial model supports many-to-many PO ↔ invoice allocation. Allocations should reconcile to the invoice total and remain within the same business relationship.

Original POKeeps all originally linked items permanently.
Extension POContains only the items officially extended under the new PO.
Physical returnHandled separately through Movement; it does not delete the commercial link.
Business Details rule: Business Details shows full business information and commercial documents. Operational item tables, movements, service, reservation, disposition and incidents are not shown at the business level.

08 · Reservation

Reserve available warehouse items before delivery

Reservation holds eligible stock for a client without physically moving it.
Eligibility: item must be Available at the selected Stock Location and cannot already have an open reservation or open incident.
Fast Pick: exact Wellora SN / R2R SN or exact Description.
Browse Eligible Items: 20 per page. Checkbox selections remain selected while you move between pages.
Cancellation: cancelling the reservation releases the stock; physical delivery is still handled through Movement.
09 · Disposition

Use exact serial identification for terminal actions

Disposition is a high-consequence workflow. It deliberately does not offer Description lookup or browse selection.

Exact SN only

Identify the item by exact Wellora SN / R2R SN. The operator must positively identify the specific serialized item.

Eligibility matters

Do not dispose an item while it is At Client, In Transit, in Maintenance/Inspection, Reserved or otherwise operationally blocked.

Disposition is terminal. Verify the serial number, physical item and disposition information before submitting.
10 · Incident

Report missing/stolen items and recovery

Incident is an internal operational control, not a commercial Business relationship.

Report incident

Use exact Wellora SN / R2R SN only. Record the incident type, date/reference and relevant remarks.

Recover item

Use the recovery action when the physical item is found. The system restores the appropriate previous stock state instead of creating a fake movement.

No Description lookup. Incident actions require exact serialized identification for the same reason as Disposition.

Before You Submit

Five checks that prevent most errors

1. Correct serial number?

Verify the physical item against the Wellora SN / R2R SN, especially for Incident and Disposition.

2. Correct source?

The selected source must match where the item is physically located now.

3. Correct reference?

Use the intended Wellora PO, Client PO, Internal Transfer No., Receiving No., Service No. / PO or other required reference.

4. Correct module?

Physical change = Movement. Maintenance = Service. Commercial agreement = Documents. Do not use one module to imitate another.

5. Arrival completed?

If the item is physically received, make sure the corresponding arrival action is complete so Inventory matches reality.

Keep the Sheet App responsive

Use the built-in paged lists and search controls instead of trying to display all historical records at once.
